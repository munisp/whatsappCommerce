### Coder B — w44/preorders-offers — J342–J346, migrations 0138–0139
- **Pre-orders**: products get `preorderEnabled`, `preorderAvailableAt` (additive columns). Pre-order checkout allowed when preorderEnabled and now < availableAt; order lines marked `preorder`; payment captured at confirm (existing path) OR deposit-only (tenant flag `tenants.preorderDepositPct` integer 0-100, default 100 = full). On availableAt reached (Temporal scheduled task OR lazy check on order read — prefer lazy + existing sweeper pattern), lines flip to ordered and enter normal fulfillment; customer notified both channels. Cancel of pre-order before availability = full refund via existing refund path.
- **Haggling / custom offers**: `custom_offers` (id, tenantId, customerId, productId, variantId nullable, qty, offeredPriceCents, counterPriceCents nullable, status pending/countered/accepted/rejected/expired/converted, expiresAt, orderId nullable, createdAt, decidedAt). Customer makes offer in chat ("I'll pay X for Y", BOTH channels via nlp intent) → merchant notified with approval card (WA buttons + TG inline keyboard, reuse W43 addrchg grammar pattern `offer:accept|reject|counter:<id>`) → accept creates a priced checkout link (price override snapshot on the order, audit trail) valid until expiry; counter sends customer a counter-offer card with accept/decline. One pending offer per customer+product (partial unique). Price floor guard: offeredPrice >= product.minPriceCents if set (additive nullable column) else any positive amount.

### Coder C — w44/deposits-subs-digital — J347–J351, migrations 0140–0142
- **Appointment deposits**: `service_appointments` (id, tenantId, customerId, serviceProductId, startsAt, endsAt, depositCents, status booked/confirmed/completed/cancelled/no_show, orderId nullable, createdAt). Booking in chat (BOTH channels: list service slots → pick → pay deposit via existing payment intent) — deposit captured, remainder paid at completion via payment link or wallet. Cancel > tenant-config window (`tenants.appointmentCancelWindowHours` default 24) = deposit refund; inside window = deposit forfeit (refund skipped, audit row). No-show marks status, deposit kept. - **Subscription auto-billing**: `subscription_plans` (id, tenantId, productId, intervalDay/Week/Month, priceCents, status active/archived) + `customer_subscriptions` (id, tenantId, planId, customerId, status active/paused/cancelled/past_due, nextBillingAt, paymentTokenId nullable FK customer_payment_tokens (W41), createdAt). Customer pause/cancel in chat both channels. All charges idempotent (`sub_billing:<subId>:<period>`).
- **PIN digital goods**: `digital_pin_batches` (id, tenantId, productId, uploadedBy, createdAt) + `digital_pins` (id, batchId, pinEncrypted (v2:<kid> envelope — W42 secrets), status available/sold/revealed/voided, orderLineId nullable, soldAt nullable). WHERE status='available' LIMIT 1 RETURNING in txn), deliver via chat BOTH channels (decrypt server-side only at delivery); customer "reveal again" re-sends same PIN (status revealed, audit). Low-stock alert to merchant when available < threshold (10). Out-of-stock = order line backordered (W43 path) or blocked per tenant.allowBackorders.
