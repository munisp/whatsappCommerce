### FINDING #6 (real, verified) — producer/consumer TOPIC-NAME MISMATCH silently drops domain events
- The canonical topics (created by fluvio-consumer/bin/provision_topics.rs, consumed by fluvio-consumer, and the
  only names Fluvio accepts — lowercase/digits/hyphens) are HYPHENATED: wacommerce-orders, -payments,
  -conversations, -inventory, -hermes-po.
- But server/kafka.ts's publishXEvent helpers emitted DOTTED names (wacommerce.orders, …). encodeURIComponent
  keeps the dot; the /produce handler uses the topic verbatim; Fluvio rejects dotted names ("Invalid topic
  name", confirmed in the consumer's own QA-045/046 note). So publishFluvioEvents got HTTP 400, incremented a
  failure counter, logged a warning, and FAIL-OPEN dropped the event. The consumer (reading hyphenated) never
  saw it. Live callers affected: publishOrderEvent (orderCrud.ts:350 order-created) and publishConversationEvent
  (index.ts:907). (publishInventory/HermesPO: no callers; payment events already used payment.ts's own correct
  hyphenated publisher — the QA-045/046 fix was applied there but NOT to these shared helpers.)
- NOT a money bug; a broken-event-pipeline correctness bug for event-driven downstream (order/conversation
  analytics + any event-triggered side effects).
